아이폰에서 "Can't access your Google Account"가 뜨며 드라이브 창이 열리지 않는 이유

2026-09-03 · 진단 Q&A · REQ-0015 기준

Q. 아이폰에서 기록 추가 → 📥 캡쳐 가져오기를 누르면 드라이브 창 대신 "Can't access your Google Account — Try signing into your Google account or allowing cookie access" 화면이 뜨고 사라지지 않는다. 로그인은 되어 있고 PC에서는 잘 된다.

A. 아이폰 브라우저가 구글 드라이브 창의 쿠키를 막기 때문이다. 계정·앱·키 설정의 문제가 아니며, 아이폰이면 Safari든 Chrome이든 똑같이 일어난다. 그래서 앱은 아이폰에서 이 창을 열기 전에 사진 앱에서 고르기를 먼저 권하고, 그래도 열었을 때는 화면 아래에 ✕ 닫기 · 📷 사진에서 고르기 탈출 바를 띄운다.

무엇이 어디서 막히는가

[정상]   기록 추가 → 📥 캡쳐 가져오기
         → ① 구글 로그인 토큰 (accounts.google.com · 별도 팝업)   ✔ 아이폰에서도 정상
         → ② 드라이브 창 = docs.google.com 을 우리 페이지 안에 iframe으로 삽입
              구글이 "이 사람이 누구인지" 확인하려고 iframe 안의 구글 쿠키를 읽음
         → ③ 파일 선택 → 다운로드 (Drive API · 토큰만 사용)          ✔ 아이폰에서도 정상

[아이폰]  ②에서 iframe 안의 구글 쿠키가 차단됨 (다른 사이트 안에 박힌 "제3자" 쿠키)
         → 구글은 토큰이 유효해도 세션을 못 잡아 안내 화면을 그림
            "Can't access your Google Account … allowing cookie access"
         → 이 화면은 닫기 버튼이 없어 새로고침 외에는 빠져나올 수 없었음

동기화·백업·프로필 표시는 ①과 ③만 쓰므로 아이폰에서도 멀쩡하다. 헤더에 프로필과 기록 건수가 보이는 것이 그 증거다. 깨지는 것은 드라이브 창(Picker) 하나뿐이다.

왜 아이폰만 그런가

  • Safari — "사이트 간 추적 방지"(ITP)가 기본으로 켜져 있고, iOS 13.4부터 제3자 쿠키를 예외 없이 막는다.
  • Chrome · Edge 등 다른 브라우저 앱 — 아이폰에서는 모두 Safari 엔진(WKWebView)을 쓰도록 강제된다. iOS 14부터 이 엔진에도 같은 추적 방지가 기본 적용되며, 스위치는 아이폰 설정 → 해당 앱 → 크로스 사이트 추적 허용에 있다(기본 꺼짐).
  • 안드로이드 Chrome · PC — 기본 설정에서는 제3자 쿠키가 허용돼 창이 열린다. 시크릿 모드나 "타사 쿠키 차단"을 켠 경우에만 같은 증상이 난다.

앱이 하는 일 (2026-09-03 개선)

상황동작
아이폰에서 📥 캡쳐 가져오기창을 열지 않고 선택 창을 띄운다 — 📷 사진에서 고르기(기본) / 드라이브 창 열기. 사진 앱에서 고른 캡쳐도 드라이브에서 가져올 때와 똑같이 OCR로 읽어 채운다.
아이폰에서 📁 캡쳐 폴더 지정같은 안내. 폴더 지정은 드라이브 창이 열리는 환경에서만 의미가 있다.
드라이브 창을 굳이 열었는데 먹통화면 아래 탈출 바(✕ 닫기 · 📷 사진에서 고르기)로 빠져나온다. 8초 안에 아무 신호가 없거나 구글이 오류를 알리면 앱이 창을 닫고 안내를 띄운다.
드라이브 창으로 파일을 한 번 골라낸 기기추적 허용을 켠 것으로 보고 다음부터 안내 없이 바로 창을 연다(이 브라우저에만 기억).

드라이브 창을 꼭 쓰고 싶다면

브라우저스위치 위치
Safari아이폰 설정 → Safari → 사이트 간 추적 방지 끄기 (그리고 "모든 쿠키 차단"이 꺼져 있는지 확인)
Chrome아이폰 설정 → Chrome → 크로스 사이트 추적 허용 켜기
그 밖의 브라우저 앱아이폰 설정 → 해당 앱 → 크로스 사이트 추적 허용 켜기

바꾼 뒤 앱 페이지를 새로고침하고 드라이브 창 열기를 누른다. 다만 이 스위치는 모든 사이트에 적용되는 개인정보 설정이라, 아이폰에서는 사진 앱에서 고르는 흐름을 권한다 — 달리고 난 직후의 캡쳐는 어차피 사진 앱에 있다.

같은 뿌리의 다른 오류 문구

  • The API developer key is invalid — 세션 없이 진행된 키 검증이 실패하며 나오는 문구. 키는 멀쩡하다(2026-07-29 콘솔 실물 확인). 대처는 이 문서와 같다.
  • 400 origin_mismatch — 이건 다른 문제다. 접속 주소가 구글에 등록돼 있지 않을 때 나며, 앱이 별도 안내를 띄운다.
ℹ️ 앱은 drive.file(앱이 만든·사용자가 골라 준 파일만 접근) 스코프만 쓴다. 드라이브 창 없이 폴더를 직접 훑으려면 제한 등급 스코프가 필요해 구글 앱 심사 대상이 되므로 채택하지 않았다. 원리는 PC·모바일 데이터 연계 문서 참조.
