2중 목표 관리 — 27년까지의 계획 β와 목표 α

2026-07-27 · 기획 + 적용 완료 · 대상: 집계 앱 v2 목표 시스템

✅ 적용 완료 (2026-07-27) — 목표 스키마 2계층 확장(기존 단일 목표는 계획 β로 자동 이관), 2중 게이지(채움=현재 · 눈금=β · 전체=α), 페이스 기준 카드, 설정 화면·이력 테이블(β%·α%) 이원화.

1. 개념 — 왜 2중인가

계획 β는 반드시 지킬 최소 기준, 목표 α는 계획을 꾸준히 지켜내며 도달할 도전 기준이다. 단일 목표는 미달 시 좌절, 초과 시 기준 상실의 문제가 있다 — 지킬 선(β)과 당길 선(α)을 분리하면 "β는 무조건 사수, α는 초과 성과"라는 운용이 가능하다.

2. 27년까지의 기준 (기본값)

항목계획 β — 반드시 지킬 기준목표 α — 도전할 기준
주간3회 이상 · 10km~5회 이상 · 15km~
월간15회 이상 · 45km~20회 이상 · 60km~
연간180회 이상 · 540km~240회 이상 · 720km~
안정 페이스 (3km 이상)5'15"/km5'00"/km
기록 페이스4'30"/km4'00"/km

모든 값은 목표 · 달성도 화면에서 수정 가능하며, 위 표는 신규 사용자 기본값이다. 기존 단일 목표 사용자는 설정값이 계획 β로 이관되고 목표 α는 기본값으로 채워진다.

3. 화면 반영

[달성도 게이지]  막대 채움 = 현재 실적 · 주황 눈금 = β 위치 · 막대 전체 = α
                β 달성 시 막대가 초록으로, α 달성 시 100% 채움 + ✓α
[표기]          "1회 · β15✓ · α20"  /  "3.18km · β45 · α60"
[페이스 카드]    안정 = 3km 이상 러닝의 최근 5회 평균  ·  기록 = 전체 최고
                낮을수록 달성 — 기준 이하이면 ✓
[이력 테이블]    주간·월간 달성률을 β%·α% 2중 표기 (β 달성 행은 초록 강조)

4. 데이터 구조

goals = {
  plan:   { weekly:{runs,distance_km}, monthly:{…}, yearly:{…},
            pace_stable, pace_record },   // 계획 β (초/km)
  target: { …같은 구조… },                 // 목표 α
  horizon:'2027', updated_at
}
  • 드라이브 동기화는 기존 규칙 그대로 — updated_at이 더 최근인 쪽 채택.
  • 구(단일) 구조의 JSON을 가져오거나 원격에서 받아도 자동 이관된다.

5. 운용 원칙

  • β 미달은 경고 신호 — 주간 카드에서 눈금 왼쪽이면 이번 주 안에 채울 것.
  • α는 페널티 없는 도전 — β를 꾸준히 지키는 것이 α 도달의 경로라는 전제.
  • 초과 성과가 계속되면 α를 상향 조정 — 27년까지 기준이므로 연 단위로 재점검.
