모바일 전면 개편 — 손 안에서 완결되는 러닝 기록

2026-07-28 · 기획 + 적용 · 계기: run.habitree.io 모바일 접속 시 구글 로그인 차단(origin_mismatch) 제보와 함께 모바일 사용성 전반 점검

📱 전제 — 이 앱의 실제 사용 맥락은 달리고 난 직후, 폰으로다. NRC 캡쳐가 폰에 있고, 드라이브도 폰에 있고, 기록을 남기고 싶은 순간도 폰이다. PC는 회고·분석용 보조 화면이다. 그런데 현재 UI는 PC 레이아웃(좌측 레일 + 넓은 표)을 좁은 화면에 축소해 넣은 형태라, 주 사용처가 부차적으로 취급되고 있다. 이 문서는 그 우선순위를 뒤집는다.

1. 현 상태 진단 — 모바일에서 실제로 깨지는 것

2. 설계 원칙

  1. 엄지 우선 — 자주 쓰는 조작은 화면 하단 1/3에. 주 내비는 하단 탭바, 파괴적 조작(삭제)은 확인 단계 뒤로.
  2. 크롬은 최소, 콘텐츠는 최대 — 모바일 헤더는 1행 고정. 문서 링크처럼 자주 안 쓰는 것은 '더보기' 뒤로 숨긴다.
  3. 표가 아니라 카드 — 좁은 화면에서 표는 데이터를 감춘다. 한 기록 = 한 카드, 중요 지표 3개(거리·페이스·시간)를 앞에.
  4. 플랫폼 관례를 따른다 — 하단 탭바, 바텀시트, 44px 타깃, 16px 입력. 새 규칙을 발명하지 않는다.
  5. PC를 훼손하지 않는다 — 모든 변경은 미디어 쿼리 안에서. 820px 초과 화면의 현재 레이아웃은 그대로 둔다.

3. 개편안

P1하단 탭바 — 주 내비게이션 이전 (M1·M2 해결)

좁은 화면(≤820px)에서 nav.rail을 숨기고 화면 하단에 고정 탭바를 띄운다. 5탭 구성:

┌─────────────────────────────────────┐
│  홈       추가      목표     데이터    더보기  │
│  📊       ＋        ◎        ▤        ⋯    │
└─────────────────────────────────────┘
   ↑ 4개는 기존 뷰 · '더보기'는 시트를 연다

'더보기' 시트가 헤더에서 밀려난 것들을 받는다 — 문서 내비(사용법·드라이브·블로그·기획서·플랫폼·설계), 테마 전환, 계정, 동기화 상태. 이로써 헤더는 브랜드 + 계정칩 + 저장상태 1행으로 압축된다.

탭바는 position:fixed;bottom:0 + padding-bottom:env(safe-area-inset-bottom). 본문(main.stage)에는 탭바 높이만큼 하단 여백을 준다.

P1iOS 자동 확대 차단 (M3 해결)

@media(max-width:820px)에서 모든 input/select/textarea의 font-size를 16px로 올린다. maximum-scale=1로 확대 자체를 막는 방법은 접근성(확대해서 보는 사용자)을 해치므로 쓰지 않는다.

P1safe-area · 터치 기본값 (M5·M9 해결)

viewport-fit=cover 추가 + env(safe-area-inset-*)를 헤더·탭바·모달에 반영. 더불어 -webkit-tap-highlight-color:transparent, overscroll-behavior-y:contain, touch-action:manipulation(더블탭 확대 지연 제거).

P2데이터 표 → 카드 리스트 (M4·M7 해결)

≤620px에서 표 대신 카드 리스트를 렌더한다. 카드 1장 = 기록 1건:

┌──────────────────────────────────────┐
│ ▢   2026-07-26 (일)          [OCR]   │
│썸네일 일요일 오전 러닝                  │
│     3.18km · 5'28"/km · 17:24        │
│     ─────────────────────────────────│
│     📝 글감    ✎ 수정      ✕ 삭제      │
└──────────────────────────────────────┘

고도·케이던스·심박처럼 부차적인 값은 카드에서 뺀다(수정 화면에서 확인·편집 가능). 액션은 하단 한 줄에 44px 높이로 배치하고, 삭제는 가장 오른쪽 끝에 두어 오터치를 줄인다. 정렬 UI는 표 헤더 클릭 대신 정렬 셀렉트로 대체한다(헤더가 없으므로).

P2모달 → 바텀시트 (M6 해결)

≤820px에서 모달을 화면 하단에 붙이고 상단 모서리만 둥글게, 폭 100%, 최대 높이 88vh, 아래에서 위로 슬라이드. 상단에 그랩 핸들(짧은 가로 바)을 두어 시트임을 알린다. 하단 여백에 safe-area 반영.

P3통계 스트립·폼·차트 다듬기 (M8)

통계 스트립은 ≤560px에서 2열 그리드로 전환하고 세로 구분선 대신 격자선을 쓴다. 폼 액션 버튼은 좁은 화면에서 전체 폭. 차트 좌우 여백을 줄여 플롯 영역을 넓힌다.

P4백로그 — 이번 범위 밖

  • PWA 공유 타깃 — NRC에서 "공유 → 러닝기록"으로 캡쳐 직행 (Android Chrome만 지원, iOS 미지원이라 효용이 반쪽)
  • 당겨서 새로고침 — 드라이브 재동기화 트리거. 스크롤 제스처와 충돌 여지가 있어 별도 검토 필요
  • 차트 터치 툴팁 — 현재 mousemove 전용. 터치에서는 탭-투-표시로 바꿔야 하는데 차트별 히트 영역 재설계가 필요
  • 스와이프 삭제 — iOS 관례지만 발견성이 낮고 오작동 비용이 큼. 명시적 버튼 유지가 낫다고 판단

5. 검증 기준

  1. PC 무변경 — 1280px 폭에서 개편 전후 대시보드·목표·데이터 화면이 동일하게 보인다.
  2. 탭바 — 390px 폭에서 5탭이 잘리지 않고 한 줄에 들어오며, 현재 뷰가 강조된다. 스크롤해도 하단에 고정된다.
  3. 자동 확대 없음 — iOS Safari에서 기록 추가 폼의 거리·페이스 입력을 탭해도 화면이 확대되지 않는다.
  4. 데이터 카드 — 390px에서 가로 스크롤이 발생하지 않고, 수정·삭제·글감 버튼이 스크롤 없이 닿는다.
  5. 바텀시트 — 계정 메뉴·블로그 글감이 하단에서 올라오고, 내용이 길어도 시트 안에서만 스크롤된다.
  6. safe-area — 홈 화면 설치(PWA) 상태에서 탭바가 홈 인디케이터와 겹치지 않는다.
  7. 구글 로그인 — run.habitree.io가 콘솔에 등록된 뒤 모바일에서 로그인·드라이브 가져오기가 동작한다. 미등록 주소에서는 원인과 해결법이 안내된다.

부록 — 구글 로그인 차단(origin_mismatch)의 정체

이번 개편의 계기가 된 오류는 모바일 문제가 아니었다. 구글 OAuth는 사전 등록된 주소(origin)에서만 로그인을 허용하는데, 운영 도메인 run.habitree.io가 Google Cloud Console의 "승인된 JavaScript 원본"에 없었다. 등록된 run-murex-theta.vercel.app에서는 정상 동작했기 때문에 "모바일에서만 안 된다"로 보였을 뿐이다.

재발 방지로 index.html에 APPROVED_ORIGINS 배열을 두고, 목록에 없는 주소에서 로그인이 실패하면 현재 주소와 등록 절차를 그대로 보여주는 안내 모달을 띄운다. 콘솔에 주소를 추가할 때 이 배열도 함께 갱신하는 것이 규칙이다. 자세한 절차는 Google Cloud 설정 매뉴얼 참조.
